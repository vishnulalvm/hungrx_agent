# database/

SQLAlchemy (async, Postgres) models, repositories, and Alembic
migrations. This is the persistence layer — business logic belongs in
`apps/api/app/services/` or the workflow nodes, not here.

## database/models/

ORM models, one file per table. Only a subset of `core/schemas/` are
currently persisted (the rest — Restaurant, Menu, Dish, etc. — don't have
tables yet; they exist as Pydantic schemas only, pending the
extraction/publish agents that will need them).

- `base.py` — `Base` declarative base.
- `user.py`, `refresh_token.py` — auth (see `apps/api/README.md`).
- `audit_log.py` — `AuditLog`: action, entity_type, entity_id, actor_id
  (FK users.id, nullable, ON DELETE SET NULL), actor_email
  (denormalized), old_values/new_values/metadata_ (JSONB), agent_run_id
  (plain string, not FK), created_at.
- `source.py` — `Source`: restaurant_id (plain UUID, not FK — no
  restaurants table yet), source_type, url, is_verified_domain,
  created_at.
- `agent_run.py` — `AgentRun`: id, workflow_type, restaurant_id
  (nullable), status, started_at, completed_at, error_message,
  created_at. Represents one run of a LangGraph workflow (e.g. one
  collector-workflow invocation for one restaurant).

All models are re-exported from `database/models/__init__.py`.

## database/repositories/

One repository per model — thin CRUD + targeted query methods, no
business rules. Repositories take an `AsyncSession` in their constructor
and generally `flush()` rather than `commit()`, so callers control
transaction boundaries.

- `audit_log_repository.py` — `create`, `list_for_entity`, `list_recent`.
- `agent_run_repository.py` — `create` (starts a run `RUNNING`),
  `get_by_id`, `mark_succeeded`, `mark_failed` (truncates
  `error_message` to 2000 chars).
- `source_repository.py` — `create`, `get_by_id`,
  `get_verified_website_for_restaurant`, `list_for_restaurant`.
- `user_repository.py`, `refresh_token_repository.py` — auth data access.

## database/migrations/

Alembic. Workflow: autogenerate, **review the diff**, then apply.

```
docker compose exec api uv run alembic -c database/alembic.ini revision --autogenerate -m "..."
docker compose exec api uv run alembic -c database/alembic.ini upgrade head
```

Always review autogenerated migrations before applying — Alembic gets
enum/index details right most of the time but not always.

## database/session.py

`get_engine()` / session factory used by both the API and worker
processes and by `tests/conftest.py` (which wraps each test in a
savepoint that's rolled back afterward, so tests hit a real Postgres
database without leaving rows behind).
